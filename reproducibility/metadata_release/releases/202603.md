## Metadata and filtering policy

- The canonical ENA table combines retained ENA sources and uses the current
  2026-03-17 snapshot where a run remains present. A retained older record is
  used for a run removed from the current ENA snapshot.
- The existing assembly-pipeline and metadata filters are retained. New rows
  receive pipeline status filters, current metadata filters, and `ASM_LEN` if
  total length is outside 100 kbp--15 Mbp.
- Sylph, CheckM2, N50, contig-count, and stricter assembly-quality criteria
  are recorded in `hq_filter`; they do not determine release membership.
- Non-empty identical Seqkit assembly sums are checked globally across old and
  new assemblies. One row per group is `KEEP_OLDEST`, selected by earliest ENA
  `first_public` then natural sample-accession order. It remains eligible.
  Every other member is `LIKELY_DUPLICATE`, has `DUP_SEQKIT_SUM` in both
  filters, and has comments listing its matching sample/run accessions.
- 18,072 global duplicate groups contain 37,373 rows. There is exactly one
  `KEEP_OLDEST` row in each group.

## Canonical SQLite publication

`release_1/atb.metadata.r1.sqlite` is the canonical frozen metadata database.
The accompanying TSV gzip tables and `release_1` view export are generated
directly from it. They include the full audit population as well as release
membership; `in_release_1=1` defines the published assembly set.
The database contains `assembly`, `run`, `assembly_ena_metadata`,
`ena_run_history`, `agc`, historical plus new `assembly_stats`, `checkm2`,
and `sylph`, and input provenance. Full `ena_latest` and original
`ena_661k_sample` are separate downloads, rather than database tables.
Raw historical ENA snapshot tables remain archived build inputs.

An integrity audit identified 1,027 unlinked historical Sylph rows (including
comma-separated sample lists). They are byte-value-equivalent to those in the
previous SQLite database, retained verbatim, and exposed through the
`sylph_unlinked` audit view. They are not assigned to individual release
assemblies. The main `sylph` table retains them for historical completeness.

### Simplified published schema

The publication-schema stage renames `assembly_ena` to
`assembly_ena_metadata`, preserving all columns, rows, alias mappings and
selection/evidence fields. Its table dump is identical apart from the filename.
`ena_run_history` contains one row per known run: `run_accession`,
`latest_sample_accession`, `latest_fastq_md5`, `latest_fastq_bytes`,
`latest_base_count`, `latest_fastq_ftp`, `latest_read_count`, and all 11 existing
`atb_*` history/change fields, copied exactly from the full latest table.

Full `ena_latest` and original `ena_661k_sample` remain unchanged separate gzip
downloads, with row counts and hashes under `separate_files` in the report.
They are removed from SQLite to reduce duplication. The source/observation
history and original processing provenance stay in SQLite. Historical provenance
entries describe earlier build stages and retain their original table names.

The stage builds an isolated copy, validates compact history against every
original latest row, compacts SQLite, checks integrity and foreign keys, and
compares selected ENA content and the six retained scientific-table fingerprints.
It preserves release membership, QC and AGC assignments. Earlier publication
artifacts are archived outside the publication directory. The regenerated
joined export uses the new table/file name. The uncompressed canonical database
remains available for local inspection; only its compressed copy is distributed.
